# 五转绘轮换真实项目复盘

## 项目结果

- 输入：一条 11 秒、720×1280、24 fps 竖屏实拍人物视频。
- 转绘：五条与同一原片全局动作和时序对齐的手动回传视频；自动媒体 QA 全部通过，Provider 任务、模型页面与 credits 记录缺失。
- 合成：手部语义角点顺序为左食指、右食指、右拇指、左拇指；转绘层全画幅对齐，手框只做 Alpha 遮罩。
- 轮换：从 3.6667 秒开始，每段 1.4667 秒；五种风格均进入时间线，帧数为 124、35、35、35、35；最后一条保持到结尾，不循环。
- 输出：11 秒、720×1280、24 fps、H.264 + AAC，最终自动验证通过。
- 人审：转绘片与审核页已经用户确认；渲染后的最终成片尚未取得用户视觉确认。

## 这次真正解决的问题

1. 多方案不能只是同一人物换装。生成提示把脸型、五官气质、发色发型、妆容、服装结构、材质和环境符号同时拉开；自动验证新增两两像素差异代理。本项目十个组合最低值 41.89，高于门槛 12。该数值只能排除近似重复文件，不能证明审美和角色身份足够不同。
2. 多条转绘必须共享成片全局时间。切换风格时读取新转绘片当前时刻，不从零秒重新播放；否则动作会跳回开头。
3. 7 秒附近的“抽搐”最初被误判为检测噪声并做平滑，导致真实旋转消失。对照原片后确认食指与拇指上下关系交换，正确输出应让上、下边交叉成蝴蝶结路径。
4. 固定语义点身份后重新检测，轨迹在 6.6667–7.1667 秒及 7.8333–8.1667 秒出现 7 个自交采样关键帧；插值后的最终 24 fps 渲染记录 26 个自交帧。
5. 审核页曾出现脚本语法、首帧、自动播放和定位问题，均已修复；`?t=7` 可直接定位问题时刻，白色角点可拖动。

## 失败经验与永久规则

- 不要看到框线交叉就先平滑。必须先逐帧对照原片，判断是检测尖峰还是动作本身。
- 角点永远按语义指尖连接，不按几何角度排序，不做凸包，不用最小位移循环重编号。
- 只有近零面积的闭合手势增加最小厚度；已自交的旋转几何保持原样。
- 自动媒体 QA 不判断角色好不好看；像素差异代理也不判断人物设定是否真正不同。两层自动检查之后仍需逐条人审。
- 手动回传可以完成本地制作，但必须把 Provider trace 写成 `missing evidence`，不得宣称使用了某个无法核验的模型。
- 审核配置的短淡化本项目最终为 0.01 秒，这是用户确认的项目值，不替代 Skill 的常规默认值 0.12 秒。

## 新增自动门禁

- `semantic_rotation_crossing_preserved`：若轨迹存在自交关键帧，渲染报告必须保留固定语义顺序并产生自交渲染帧。
- `multi_style_pairwise_visual_distinctness_proxy`：多转绘项目抽样所有视频对，平均绝对像素差必须达到 12；报告明确它只是代理，人工身份和风格审核仍为必需。
- 渲染报告记录 `semantic_corner_order`、`self_intersection_semantics`、`self_intersection_frames` 和 `self_intersection_times`，便于复查交叉动作是否在合成阶段丢失。
